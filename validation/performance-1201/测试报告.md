# 1.20.1 Forge 性能优化与验证报告

日期：2026-10-17。优化前代码提交：`6202adf`。仅修改 `1201forge` 分支。

## 结论与范围

这次主要减少特效几何生成中的临时对象、重复三角函数计算和弹幕首目标查询的额外候选收集。所有特效、几何精度、透明叠加顺序、扭曲分辨率、伤害倍率、检测频率和命中顺序保留。

下表是带相同探针的局部受控基准，不是整场战斗 FPS 或服务器整体 MSPT 的提升百分比。真实战斗前后各完成一轮功能回归；跨进程运行时间存在明显波动，因此不使用它们宣称整体性能提升。

## 环境和方法

- Ryzen 7 7730U，AMD Radeon (TM) Graphics 核显，Java 17.0.18，Minecraft 1.20.1，Forge 47.4.23。
- 客户端窗口 960×540，视距 8、模拟距离 5；各次使用同一存档快照的独立副本，开启原有扭曲效果。
- 保留项目已有开发运行依赖：Draconic Evolution、Brandon's Core、CodeChickenLib。结果不代表没有这些依赖的纯净环境。
- 真实技能回归统一使用第三阶段并逐项直接触发，跳过 AI 权重选技；人物无敌飞行，关闭地形破坏。固定场景是局部压力样本，不代表自然战斗的场景占比。
- 初次基线因失焦暂停而中止，排除该轮完整战斗数据；有效基线为 `baseline-v2`，优化后为 `optimized-v1`。
- 主要比较采用 `paired-v2`：把原版绘制代码另存为测试用 Reference 类，在同一个 JVM、同一个 OpenGL 上下文内交替 A/B；每个场景每种实现预热 100 次，测量 300 次，并交替先后顺序。
- CPU 列为特效几何构建及绘制提交的墙钟耗时；分配列由 ThreadMXBean 记录当前线程新分配字节，不是显存或常驻内存。
- 固定场景使用 glFinish 和 GPU 查询隔离相邻样本。CSV 中 GPU 列是该串行隔离条件下的命令区间耗时，可能含供给等待；不能换算成正常游戏 GPU 帧时间或 FPS。
- 所有诊断源码、脚本、运行目录位于 `D:/AI临时文件/edp-perf-20261017`，通过 Gradle init 注入；正式工程没有加入探针。

## 同进程固定特效场景结果

单位：CPU 为 ms/帧；临时分配为十进制 KB/帧。降低为正数表示优化后减少，负数表示本次采样增加。

| 场景 | 原版 CPU | 优化 CPU | CPU 降低 | 临时分配原版 → 优化 | 分配降低 |
|---|---:|---:|---:|---:|---:|
| 48 点地脉 | 1.9050 | 1.8157 | 4.7% | 609.5 → 62.8 | 89.7% |
| 192 点地脉 | 6.4144 | 5.8023 | 9.5% | 2399.0 → 216.4 | 91.0% |
| 72 枚龙鳞弹幕 | 0.1942 | 0.1799 | 7.3% | 92.6 → 21.8 | 76.5% |
| 20 枚翼刃 | 0.3188 | 0.2915 | 8.6% | 193.0 → 40.7 | 78.9% |
| 黑洞 | 0.7982 | 0.8080 | -1.2% | 86.2 → 43.0 | 50.1% |
| 4 道环波 | 0.8122 | 0.7337 | 9.7% | 248.5 → 2.7 | 98.9% |

几何数量完全一致。例如 192 点地脉两种实现都是 55,056 个顶点、304 次非空绘制提交。此次没有通过减少几何或绘制对象提高成绩。

## 服务端弹幕受控测试

每次创建 4 波、每波 18 枚，最多模拟 80 次 Hazard.tick；计入 hazard 创建与运动处理。每种实现先预热 60 次、再测量 120 次，同进程交替先后。

0 生物场景可以保持 72 枚弹体存活完整 80 tick。128/512 生物密集在起点附近，弹体会提前命中并结束，所以后两行只代表近场命中，不能解释成持续 80 tick 的高密度战斗。所有目标无敌，避免前后测试改变目标血量。

| 附近生物数 | 原版整段 ms | 优化整段 ms | 耗时降低 | 整段临时分配 KB 原版 → 优化 |
|---|---:|---:|---:|---:|
| 0 | 5.255 | 5.416 | -3.1% | 2428.4 → 2201.2 |
| 128 | 3.995 | 3.877 | 3.0% | 1497.9 → 1323.1 |
| 512 | 1.255 | 0.188 | 85.0% | 111.9 → 87.5 |

Reference hazard 调用当前 Brain.victims 的同等筛选路径，因此这组主要比较首目标提前停止与速度向量预计算，未单独放大缓存筛选谓词的收益。这是手动调用真实世界 Hazard 的微基准，不是服务器自然运行的 MSPT。

附线程实际 CPU 时间，减少操作系统调度等待对墙钟时间的干扰。线程时间精度受操作系统计时粒度限制，应看多样本均值。

| 附近生物数 | 原版线程 CPU ms/整段 | 优化线程 CPU ms/整段 | CPU 时间降低 |
|---|---:|---:|---:|
| 0 | 0.781 | 0.391 | 不采用：系统计时粒度不足 |
| 128 | 0.391 | 0.260 | 不采用：系统计时粒度不足 |
| 512 | 0.000 | 0.000 | 不采用：系统计时粒度不足 |

本机线程 CPU 计时表现为约 15.625 ms 的粗粒度，多数单次样本为 0，512 生物场景累计也可能为 0。因此该附表仅保留原始诊断值，不据此计算或宣称 CPU 提升百分比。

第一轮交替测试保存在 `paired-first-metrics.csv`。两轮中，黑洞 CPU 提交耗时均接近持平，其余五种场景的平均耗时均有所下降；内存分配下降在两轮都稳定可见。服务端空场景最终墙钟差约 3%，不能据此宣称改善；按完整 80 tick 摊分，差值约 0.002 ms/tick。128 生物近场命中的最终差异同样很小，512 生物近场命中才有明确的大幅下降。

## 具体改动

1. `Draw`：缓存圆周角度与球面法线采样，保持原始浮点运算和顶点顺序；直接写入坐标，减少环、柱体、ribbon 的中间 Vec3；复用 beam/ribbon/terrain 临时数组。地形高度每次仍重新采样。
2. `RuptureVfx`：按 delay 预索引子效果触发点；一次整理当前预警/爆发点，再按原材质和原顺序绘制。
3. `BarrageVfx`：复用弯月和尾迹短数组，预计算恒定速度向量。
4. `DragonBrain` / `BarrageHazard`：使用当前 Minecraft 原生查询的结果数量上限，在原有每枚弹体的 AABB、同一谓词和同一实体顺序下，得到首目标后立即停止收集；复用结果列表并预计算速度向量。

没有降低碰撞检测频率，也没有把多枚弹体合并成会改变目标顺序的大范围查询。没有修改技能伤害、击退、网络更新频率、shader、透明混合或场景复制策略。

## 一致性与运行验证

- 优化前、优化后真实客户端与集成服务器均完成 12 个技能及转阶段护盾，共 13 项；相同场景技能结束 tick 一致，详见 baseline/optimized-checks.txt。
- 六种固定特效场景逐顶点记录坐标、UV、法线、颜色、alpha、材质、uniform 和提交顺序，原版与优化版哈希相同。
- 六种场景截图均为 960×540；逐像素比较每张都是 0 个差异像素，共比较 3,110,400 个像素。原图与结果保存在同目录。
- 2048 个查询框验证 firstVictim 与原版完整查询的第一个结果相同；32 组弹幕场景验证命中对象、顺序、tick 与伤害倍率轨迹一致。
- `--offline clean build` 成功；正式 JAR 已检查无 PerfProbe、Reference 或 validation 类，文本资源通过严格 UTF-8 解码。详见 release-verification.txt。

这些检查覆盖当前测试场景，不能代替全部地图、显卡、第三方渲染器和多人网络环境测试。当前数据不足以证明整场战斗 FPS 或整体服务器 MSPT 有固定百分比提升。

## 原始证据

- `paired-metrics.csv`：主比较的原始均值、中位数、P95、总耗时、分配数据。
- `baseline-metrics.csv` / `optimized-metrics.csv`：独立进程固定场景、真实技能与整 tick 的记录，仅作诊断参考。
- `*-checks.txt`：几何哈希、实体数量及技能完成结果。
- `pixel-comparison.json` 与 `base-*.png` / `opt-*.png`：逐像素对照证据。

复现：在临时根目录运行 `python prepare.py <新标签>`，使用生成的 init 执行项目 `runClient`；同进程对照额外运行 `python paired.py <新标签>`。每次用新标签及独立存档副本，避免混入已有结果。参考源码固定来自 `6202adf`，脚本不会自动适配其它 Minecraft 版本。
